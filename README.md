# Cuppable

Браузерный симулятор кофейни в университете: вы бариста от первого лица, готовите напитки по рецептам, обслуживаете гостей между парами и растёте в ранге от стажёра до шеф-бариста.

**Играть:** https://mentanicarli.github.io/cuppable/

## Управление

- Клик по гостю или **Пробел** — принять заказ и перейти к бару.
- В баре кликайте по станциям (кофемолка, темпер, группа, молоко, паровая трубка, сиропы, лёд, витрина, звонок) и следуйте тикету сверху.
- **Пробел** — остановить шот; **Esc** или «К залу» — вернуться; **P** — пауза.

## Музыка

Фоновые треки лежат в `public/music/*.mp3` (до ~15 файлов). Скрипт `scripts/make-music-manifest.mjs` сам запускается перед `npm run dev` и `npm run build` и пишет `public/music/manifest.json` (его в git нет). Название берётся из ID3-тегов, иначе из имени файла вида `Исполнитель - Название.mp3`, иначе это имя файла без расширения. Треки играют по кругу с плавным стыком, музыка стартует после первого нажатия игрока. Пустая папка — игра идёт без музыки, а ползунок и строка «сейчас играет» скрыты.

Чтобы добавить трек: положите mp3 в `public/music/`, перезапустите `npm run dev` (или сделайте `npm run build`). Файлы лежат рядом со страницей, пути относительные, поэтому подпапка `/chofix-game/` на GitHub Pages работает.

**Важно:** кладите только ту музыку, на которую у вас есть права (своя, лицензия, CC с подходящими условиями). Репозиторий и сайт публичные.

## Быстрый старт

Нужны Node.js 20+ и npm.

```bash
npm install
npm run dev        # dev-сервер
npm run build      # релиз: dist/index.html, dist/artifact.html и dist/sfx
```

Игра грузит звуки по относительному пути `sfx/…`, поэтому открывайте `dist/` через любой статический сервер (из файла звука не будет).

## Рецептуры и объёмы

Размер напитка в литрах — это объём в чашке V (мл). Всё, что от него зависит, считается в одном месте, `src/game/volumes.ts` (`recipeNumbers`), и оттуда берут бар (цели налива), книга рецептов (`recipeCard` в `src/game/recipeCard.ts`) и себестоимость (`recipeCost` в `economy.ts`).

- **Шоты по размеру:** 0,2 и 0,3 л = 1 шот (30 мл, около 9 г), 0,4 и 0,6 л = 2. «Эспрессо» — один шот в чашке 90 мл, «Двойной эспрессо» — два одинаковых шота подряд в чашке 120 мл (каждый — полный цикл «помол → темпер → шот», на билете «Шот 1/2», «Шот 2/2»), флэт уайт всегда двойной. Вода или молоко = V − 30·S.
- **Молоко и пена:** молоко до пара = (V − 30·S) / (1 + x); капучино x = 0,5, латте 0,2, флэт уайт 0,1, раф 0,3. Раф классический: эспрессо сразу в питчер, холодные сливки и сахар или сироп, пар, заливка; молока в нём нет. Зоны пара: капучино 60–65°, латте 55–62°, флэт уайт 55–60°, раф 60–65°.
- **Холодные:** жидкость 0,55·V, лёд 0,3·V (кладётся первым), размеры 0,3 / 0,4 / 0,6. Остальные напитки (бамблы, тоники, аэрокано, шейки, бабл ти, протеин, чаи) заданы долями V и граммами, см. [docs/recipes_audit.md](docs/recipes_audit.md) (`npm run audit:recipes` пересобирает его из кода).
- **Чашка:** масштаб модели (V / 200)^(1/3): 1,00 / 1,14 / 1,26 / 1,44 для 0,2 / 0,3 / 0,4 / 0,6 л; в баре, на стойке, в руках баристы и гостя, на столике, в билете и в пузыре заказа.
- **Меню и данные:** источник правды `data/build_menu.py` (+ `menu_raw.json` из `chofix_menu.md`); `npm run menu` пересобирает `menu.json`, `progression.json`, `PROGRESSION.md`. Тесты: `test/volumes.test.ts` (формулы, сумма компонентов = V ±3%) и `test/recipeCard.test.ts` (книга совпадает с `buildTasks` и целями бара).

## Для разработчиков: песочница

Режим для разработчика и тестировщика: мгновенно попасть в любой день и ранг со всеми улучшениями, не играя с нуля.

- **Как включить.** Только ссылкой с хешем `#dev`: `artifact.html#dev`. С другими хешами через дефис: `#dev-nopixi-lowfx`. Без `#dev` в игре нет ни кнопки, ни панели, ни интерфейса песочницы, ни хуков, которые что-то делают.
- **Принцип: день определяет состояние.** Выбираете день (1–60) и профиль игрока («Средний» или «Уверенный», по умолчанию «Средний»); ранг, рейтинг, «обслужено», деньги и покупки выводятся из них, чтобы состояние было достижимо для обычного игрока. Ранг, рейтинг и «обслужено» берутся из таблицы типичного прогресса `data/typical-progress.json` (медианы по 60 прогонам модели игрока). Ранг никогда не выше максимального с `minDay` ≤ дня, рейтинг и «обслужено» не ниже порогов ранга и не выше правдоподобного потолка. Деньги по таблице, но не меньше двух аренд, и на покупки не списываются.
- **Режимы покупок.** «Всё доступное» (по умолчанию): куплено всё, что на этом дне и ранге есть в магазине по `isShopItemAvailable` и условиям «С дня N» / «Ранг N», вместе с цепочками зависимостей (молоко, потом то, что после молока, и т. д., до неподвижной точки); позиций из будущего нет. «Как у типичного игрока»: покупки из таблицы на этот день. День 1: ничего не куплено.
- **Экран «Песочница».** День, профиль, режим покупок, темп, «Показывать обучение» (по умолчанию выключено; включено — пройденным помечено только то, что открыто к этому рангу) и «Сбросить обучение». Раскрывающийся блок «Своё» (свёрнут): ранг (не выше допустимого для дня, подпись «на 10-й день максимум ранг N»), рейтинг, «обслужено», деньги и отдельные покупки; недоступные позиции выключены, при смене дня, профиля, режима или ранга список пересчитывается, лишнее снимается.
- **Панель «DEV»** (кнопка в правом верхнем углу во время смены, на паузе скрыта; в заголовке «День N · ранг R · режим»): скорость ×1/×2/×4/×8, «Стоп» и «Шаг 1 с», «Закончить день» (обычный итоговый экран); +100/+1000 денег, рейтинг ±0,1, «Следующий ранг» (в режиме «Всё доступное» открывает ставшие доступными позиции; если ранг выше допустимого для дня, тост «Для этого дня ранг нереалистичен», но действие выполняется); «Позвать гостя сейчас», «Без терпения», тип гостя и частота прихода; «Следующий заказ» (напиток, размер, холодный, сироп, молоко, еда; подменяет бросок один раз); «Неограниченные деньги» и «Бесплатные ингредиенты»; «Сбросить обучение»; «Сохранить и выйти в меню». Ускорение времени двигает только смену (приход, терпение, часы), у бара шаги идут как обычно.
- **Статистика смены** (в памяти, в сейв не пишется): среднее и медиана времени от появления гостя до выдачи, готовка у бара, разбивка по числу шагов, доли плохих/нормальных/идеальных, ушедшие, доход. «Скопировать JSON» кладёт в буфер объект, где `profile: { name, speed, q: [плохо, нормально, идеально] }` можно вставить в `PROFILES` модели игрока (`src/game/playerModel.ts`). `speed` считается по времени у бара как отношение к модели `12 + 7 · шагов` секунд.
- **Таблица типичного прогресса.** `npm run sim:table` перегенерирует `data/typical-progress.json` (в `npm run check` не входит, JSON лежит в git, чтобы песочница работала без симуляции). Делайте это после изменения цен, порогов рангов (`progression.json`), правил магазина (`shop.ts`, список `SHOP_BASE`), формул экономики и прихода гостей или самой модели игрока (`playerModel.ts`). Отчёт по покупкам: `SIM=1 npx vitest run scripts/shop-sim.test.ts` → `out/shop-sim.md`.
- **Изоляция.** Песочница не читает и не пишет настоящий сейв (`SAVE_STORE` в ней молчит) и не меняет настройки игрока. Последняя конфигурация экрана хранится отдельно: ключ `localStorage` `chofix.sandbox.v1`. Деньги, ранг и обучение песочницы в настоящий сейв не попадают.
- **В e2e** вместо прохождения дней с нуля: `require('./pw').sandboxStart(p, url, { day, profile, mode, custom })` открывает `#dev-nopixi-lowfx` и запускает песочницу тем же кодом, что кнопка «Начать» (`window.__sandbox.start`). Нужное сценарию особое оборудование задавайте переопределением `custom` (значения приводятся к допустимым для дня). Примеры: `e2e/sandbox_flow.js`, `e2e/menu_test.js` (день 60, «Уверенный»: ранг 9 и всё оборудование), `e2e/bar_test2.js` (день 6, «Средний»).
- **Код.** Чистая часть (`resolveSandbox`, `makeSandboxState`, `sanitizeItems`, подмена заказа `OrderOverride` в `rollOrder`, статистика) — `src/game/sandbox.ts`, модель игрока — `src/game/playerModel.ts`, тесты `test/sandbox.test.ts`; экран и панель — `src/ui/sandbox.ts` и `src/legacy/16-sandbox.js`.

## Деплой

Каждый push в `main` запускает [workflow](.github/workflows/deploy.yml): `npm ci`, проверки, `npm run build`, публикация `dist/` на GitHub Pages. Один раз включите в репозитории Settings → Pages → Source: «GitHub Actions». Повторный деплой — новый push или Actions → «Deploy to GitHub Pages» → Run workflow.
