# Систематический поиск подобного (шаг 1, дополнение 19б)

Цель: найти не только то, что заметил владелец (`remarks-register.md`), но и всё подобное по игре, **скриптами, а не глазами**. Код игры не менялся. Все результаты ниже получены на отладочной сборке (`CUPPABLE_DEBUG=1`), программный WebGL (SwiftShader, полуразрешение), песочница `#dev`, день 10 «Всё доступное». Сырые данные и снимки: `out/art-audit/sys/` (в git не идут).

## Как запускать (скрипты лежат в `e2e/`, можно использовать на следующих шагах)

```bash
CUPPABLE_DEBUG=1 npx vite build && CUPPABLE_DEBUG=1 node scripts/fragment.mjs   # Windows PowerShell: $env:CUPPABLE_DEBUG=1; npx vite build; node scripts/fragment.mjs
node e2e/art_checks.js dist/artifact.html out/art-audit/sys overlap            # матрица наложений, обрезка, кликабельность (5 размеров окна; SIZES=1280x720 для быстрого прогона)
node e2e/art_misc.js   dist/artifact.html out/art-audit/sys cups,load,texts,recog   # налив/чашки, нагрузка бара, тексты, крупные планы
node e2e/art_panel_clicks.js dist/artifact.html out/art-audit/sys              # реальные клики по чайной панели
```

Размеры окна: 1280×720, 1366×768, 1536×864, 1920×1080, 1024×600. Масштаб сцены `min((W−32)/1280, H/720)`: 1,0 / 1,04 / 1,18 / 1,5 / 0,775; сцена всегда целиком в окне, «высоты окна, меньшей масштаба сцены» не бывает (сцена вписывается по меньшей стороне). Рамки в отчётах пересчитаны в координаты сцены 1280×720.

Что и как мерит `art_checks.js`: DOM — `getBoundingClientRect` каждого видимого элемента с собственным текстом (блок = ближайший предок из списка `#hud, #bTk, #bCoach, #xPanel, #bi, #toast, #banner, #bFloat, #drinkCard, #screen, .say…`), Pixi `Text` — `getBounds()` по дереву `WORLD.app.stage`; пара «пересекается», если блоки разные и площадь ≥ 150 px². Обрезка — выступ за ближайшего предка с `overflow: hidden/clip`. Кликабельность — `document.elementFromPoint` в центре и четырёх углах (4 px от края) каждой кнопки/зоны.

**Оговорки по методу (честно).**
- Углы скруглённых кнопок попадают на родителя (прозрачные углы): такие «блокировки» я **отбрасываю** и считаю по центру.
- Пара «Pixi-текст × Pixi-текст» считается по рамке текста, не по глифам: часть мелких (150–700 px²) пересечений — пустые поля рамки.
- «Закрыто окном» (экран итогов, карточка напитка, баннер поверх мира) — по замыслу, в таблицу проблем не вношу.
- Кнопки `#chSound`/`#chPause` скрипт 146 раз отметил как «перекрытые родителем `#hudR`»: **ложное срабатывание**, проверено реальным кликом (пауза включается, `elementFromPoint` отдаёт внутренний значок кнопки).
- Книга рецептов прокручивается внутри окна: «вылезание за окно» там не ошибка.

## B2. Проверка налива и чашки

**Метод.** Для каждого из 37 напитков (`data/menu.json`) × размеры 0,3/0,4/0,6 (+ холодные) вызван `rcFor(c)` (те же цели, по которым строится бар): 136 строк, `out/art-audit/sys/cups_rc.json`. Пиксельного сопоставления «кадр бара против данных» **не делал** для всех 136 вариантов (для этого нужно проигрывать каждую станцию); вместо этого разобрана формула отрисовки (`barPaint`/`xLayers` в `08-bar-view.js`: слой в px = мл · 72 / `cupMl`) и сопоставлена с данными.
